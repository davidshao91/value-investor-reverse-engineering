# 用 EDGAR 的表格类型做事件表

这是第一批里可复用的做法，来自格林布拉特案例（并购委托书）和巴菲特案例（私有化、要约）。2009 年以后的电子申报最好用。全程免费，付费的并购数据库不是前提。

先设联系方式，再跑脚本：

```bash
export EDGAR_USER_AGENT="Your Name you@domain.com"
```

## 1. 从季度索引找出事件

每一季一份纯文本索引：

`https://www.sec.gov/Archives/edgar/full-index/{年}/QTR{季}/form.idx`

- 用响应的原始字节，按 `latin-1` 解码。不要用 HTTP 库自动猜编码：一份大约 30MB 的索引，猜编码会卡住很久。
- 一行算命中，当且仅当行首是「表格类型 + 两个空格」。类型照索引原文写，不要自己加连字符：`SC 13E3`、`SC TO-T`、`SC TO-I`、`SC 14D9`、`DEFM14A`、`PREM14A`、`25-NSE`、`10-12B`、`10-12B/A`。
- 同一份申报会按每个相关 CIK 各列一行。目标公司和申报人都会出现。

本仓库：`cases/greenblatt/code/g01_idx.py` 拉分拆用的 `10-12B`；`cases/greenblatt/code/arb/a01_idx.py` 拉并购和退市用的类型。

## 2. 只下主文档

索引最后一列是档案路径。下载 `https://www.sec.gov/Archives/` 加上该路径，读到第一个 `</DOCUMENT>` 就停，gzip 存盘。User-Agent 用上面的真实联系方式，全局限速大约每秒 10 次以内（5 个线程、每次间隔约 0.4 秒，大约每秒 7 份）。

对应脚本：`cases/greenblatt/code/arb/a02_fetch.py`。

## 3. 用申报史判断结局

`https://data.sec.gov/submissions/CIK##########.json`（CIK 补满 10 位）。`filings.files` 里的旧分页要合并进来。8-K 有 `items` 字段：`1.02` 常是终止协议，`2.01` 常是完成收购，`5.01` 常是控制权变更。

完成退市，看这些表格：`25-NSE`、`25`、`15-12B`、`15-12G`、`15-15D`。

两件容易判错的事：

- 收购完成后如果公司还有公开发行的债券，它会继续交 10-K。不能用「后来还有没有年报」来否定收购已经完成。
- 合并完成时，8-K 的 1.02 也常用来终止信贷协议，不能直接当成「交易失败」。

## 4. 并购委托书里直接有价格

`DEFM14A` 的前部（摘要、问答）通常写着三样东西：每股现金对价、宣布前收盘价、以及「最近可行日」（委托书付印前）的收盘价。最后这个就是宣布之后的入场价。

抽价格时，取那句短语**后面**的第一个美元数。取「离得最近的数」会抓到前一句里的宣布前价格，价差会被夸大。

价差较宽的那一截（例如至少 5%）必须人工抽查。常见错误是把成交量加权价、宣布前价格、或有对价权的上限当成了入场价，也可能漏掉后来的降价重谈。本批里，价差至少 5% 的交易大约五分之一有这类问题，核查之后组合更差。

现金并购完成后，终值就是现金对价，不需要退市之后的行情。分拆和破产做不到这一点：持有期里的价格必须另找（含退市股票的历史行情）。

## 5. 两个覆盖率分开报

1. **事件密度**：这种事件每年有多少宗，够不够组成篮子。
2. **价格覆盖率**：这些事件里，有多少能接到入场价和结局。本批把 70% 当作门槛。

还要写明缺失跟结局有没有关系。委托书根本没写当前价，这种缺失接近随机。免费行情系统性丢掉被收购、破产的公司，这种缺失会把结论带偏。

## 6. 宇宙不要先被行情源裁掉

先用 XBRL 的报送公司定宇宙，再去找价格。没有行情时，用 `dei:EntityPublicFloat`（frames 的 `CY{年}Q2I`，大约是当年 6 月末的公众流通市值）当市值上界。流通市值不会大于总市值，所以「看起来很便宜」的数量是上界。

如果一开始就只保留「今天 yfinance 还有价格」的公司，深度折价和回购的交集可能是空的。那不一定是规则组不出篮子，也可能只是幸存者名单把退市公司裁掉了。密度过了，再单独报价格覆盖率。

巴菲特案例就是按这个顺序重做的：宽宇宙下篮子刚能组出来，然后规则本身没有过线。
